Compiler version 0.0.229 alpha for version 0.0.41 of the specs 2026/11/28

Changes from the previous version -----------------------
- Traits (spec 11.2, decided by the user 2026-11-28): a sub-trait gives a method of its parent trait a new default body with replace fun (same parameters and result; its classes use it unless they replace it; through the parent trait type the class version runs; replace of nothing and a redeclaration without replace are compile errors). A constructor of a sub-trait chains to its parent trait, Named(string n) : Sized(n.len), also over several levels: the parent trait runs first and is initialized once (a class that also calls it, or a parent trait that comes from the parent class, is a compile error; a trait whose constructors do not all chain says "not supported"). fun bool ==(Shape o) in a trait, with or without a default body: required of its classes, == on two values of the trait type calls the version of the class of the left object (equals first when that class defines it), != its negation, null by identity. Tests traitreplacemethod, traitctorchain, traitequals, errors/trait_replace_nothing, trait_redeclare_no_replace, trait_chain_called_twice, trait_chain_not_parent, trait_equals_missing
- for &x over a custom collection (spec 6.7, decided by the user 2026-11-28): writableNext() of IndexIterator is optional; its default in the trait raises the new MissingWritableIteratorForCustomCollectionException (15.3 #73) at the first call, when the loop starts (also on an empty collection); next() stays required. Tuples with a writable borrow (spec 3.2): (&i32 value, bool isValid) as a type, (&bag.items[i], true) takes the address of the place, t.value reads it. Not built: writableNext() of MapIterator and for (k, &v) over a custom map ("not supported"). Test customwritable
- Static weak fields (spec 12.7, 11.1.2): static %T and &%T of a class (was "not supported"): set with = %x inside and outside the class, read through enforce by the bare name inside the class and as Kennel.last, released at the end of the program. Static field groups (spec 11.1.4.1): public static pos { r32 x = 1.5, r32 y } (was "not supported"): its fields are static fields, Conf.pos.x read and written, ++, pos.x inside the class, the whole group assigned and read as a tuple. Test staticweakgroups
- atEnd after a statement (spec 14.2, form 3): } atEnd { } after an if / else, a loop, a switch, an enforce or a block (was "not supported"). It sees the locals of every scope of the statement that it uses (declared before the statement, a branch not taken leaves null), runs once on every way out (the end, return, break, a raise passing through), after the form 1 blocks inside. The same name with two types is a compile error. Not built (says so): a local it uses declared with var, without a value (not an object), const, a & reference, or with its own atEnd. CodeGen.TrailingAtEnd.cs, tests atendstatement, errors/atend_statement_two_types, atend_statement_var
- executeBefore / executeAfter (spec 11.2) on a generic method of a trait (every copy runs the blocks, same.result is the value of the copy) and on a method with several results (two.result.0, two.result.1; two.result alone is a compile error), also through the trait type and in a chain of sub-traits with a default body (was "not supported"). Not built: a lent string result of a hooked method (the wrapper keeps the result in a local: same<string> of a plain string asks for ->string). Tests executegenericmulti, errors/execute_multi_result_whole
- A set as the type of a parameter (spec 11.3.6): a constructor of the body takes a set value, as the primary constructor (was "not supported"); read it with switch n is ? { } or if n is T x. Checked, already built: methods, static methods, struct methods and trait methods (one copy per member), a replacing method chosen by the class of the object, methods of a generic class. Test setparamctor
- for &x (spec 6.4): for (k, &string v) in m and for &string v in m.values on map and hmap (was "not supported"): each pass lends the value in a cell and puts it back in its slot when the pass ends, also through break, continue, return and a raise. for &x over a view is a compile error (spec 6.5: a view is always read-only; was "not supported"). Tests forstringvalues, errors/for_rw_view (errors/map_loop_writable_value is gone: it checked the old refusal)

Tests globalfieldsmore, errors/global_field_lent
