Compiler version 0.0.102 alpha for version 0.0.34 of the specs 2026/11/12

Changes from the previous version -----------------------
- tuple items by index (spec 3.2): t[1], t[SECOND] (a const), t[Slot.Second] (an enum value), read and assigned (t[0] = v, t[2] += x); nested (pairs[2][1]); a variable index or one out of range is a compile error (was "feature not supported: Collections")
- no more "warning L3: read as a generic call" on calls like FixedSlot<64>("x"): when the name is not a generic, the error says that a<b>(c) is read as a generic call and how to write the comparisons
- new passing markers (spec 13.1): &T and &x write (was (&)), the old read-only &T is written plain T (read-only only for as parent so far), &@T (was (@)T), %T and %x weak (was _T, _x), &%T (was (_)T), *x and &*x / &*T pointers (still not supported); the old markers give an error that names the new one
- counted and weak arguments repeat the marker of the parameter (spec 13.1): keep(@rex), train(&@max), watch(%rex), heal(&%max), pack.add(@rex), pack.replace(0, @max); a new object, a result and null need none; a missing or wrong marker is a compile error that shows the right one
- & replaces the caller's value (spec 13.1) also for objects and collections (vec, list, maps, sets), and the old value ends for every kind (objects, strings, arrays: they leaked before); &x needs what owns its value (owning variable, field, array item, & parameter); &this is an error; an array printed with $"{a}" is now freed at the end of its scope
- -> results (spec 13.1.1): fun ->Dog make(), fun ->arr<Dog>, uns pack(); a plain result that returns a new object, string or array (or a local that owns one) is an error that asks for ->; -> on a basic result is a level 1 warning; R accessors need none; the IO library functions that build values are now ->
- borrow locks (spec 12): while a local borrows an object or an array (Dog view = rex, Dog d = k.leader(), Dog f = pack[0]), what it borrows from cannot be assigned, ended, moved or passed as & until its last use (inside one function); a plain result that lends from a local is an error; s.trim() and the other runtime results are new values (fun ->string)
- while a borrow is alive the fields of its lender cannot be written either (Rust style): k.boss = x, k.visits++, k.dogs[0] = x
- &T results (spec 13.1.1): fun &Dog at(uns i) { dogs[i] } lends read/write, k.at(0).name = "Max" writes in place; only from this, its fields, a & parameter, a global or another &T result; objects, collections and arrays (basic values and strings: not supported yet)
- a real ending in a dot (0., 2. + x) is a compile error that shows 0.0 (spec 1.3); it was read as a member access, also across a line end
- C strings (spec 4.4.6): string(addr) borrows a C text, string(->addr) takes it and frees it; read-only, copied into a regular string at the first change
- string? (spec 7.1): null is not ""; variables, parameters and results (fields, collections and tuples: not supported yet); string(addr) now gives a string?
- lambdas and function types (spec 13.3.6), in part: fun(i32) f = (i32 x) { ... }, i32(i32) parameters, fun ->fun i32(i32) results; captures unlisted (read-only), &a, a!, ->a; a call of a null one raises UnassignedFunctionCallException (51); a borrowing lambda cannot be assigned to an existing variable or returned
- string? fields and string? items of arr, vec and list (spec 7.1); maps and sets of string?: not built yet
- leaks fixed: a new collection or array printed directly (log(v.clone()), log(a.filter(...))); ex.message and ex.function read in a catch; an array given to copyFrom, has or indexOf inside a function no longer stops its caller from owning it (f(&a, a) gave a wrong "only borrows its array")
- var x = f() owns the object (or trait object) that f gives; it was not ended before
- exceptions leaving a lambda go back to the caller as for functions (they were a panic); in sort, filter, map and reduce they stop the work and are raised after it; a silent one is ignored by the caller unless a catch handles it (spec 13.3.6)
- lambdas in methods: the fields are captured by their bare names (read-only, &field, field!, ->field); a! of objects (a clone) and arrays, ->a of arrays (spec 13.3.6)
- sort(lambda) on arr, vec and list (spec 6.6), any item type; filter(bool(T)), map<U>(U(T)), reduce(start, A(A, T)) on arr, vec and list
- a return whose value uses temporaries (fun ->string f(i32 x) { "#" + x.toStr() }) leaked them: they now end before the function returns
- plain parameters of objects, collections and arrays are read-only (spec 1.6.2, 13.1): public methods need unrestricted or a & parameter; collection members that do not change them, getIterator and the File members still work; the 5 parked tests are in tests/errors
- structs, step 1 (spec 11.1.5): struct Vec3 { r32 x, r32 y, r32 z = -1.0 }; Vec3(x: 2.0) by name (the others take their start value or zero) or Vec3(1.0, 2.0, 3.0) with all the fields; fields read and written (s.x, b.min.z, ps[1].y, v[0].z += 1); copies by =; locals, globals, class fields, plain (read-only) and & parameters, results; arr<S>[n] items take the start values; == field by field and printing (Vec3 { x: 2, y: 0, z: -1 }) also built. Not yet: methods, strings and objects inside, buffers arr<T>[N], struct<fixed> / <compact>, transmute, .sizeof / .offset / .hash, field groups and tuples
- structs, step 2 (spec 11.1.5.2): methods (fun inside the struct, private unless public / unrestricted); this is the struct itself and changes in place, fields and sibling methods by their bare names; s.len(), ps[1].scale(2.0), ship.pos.double(), Vec2(1.0, 1.0).plus(p) (a new struct: the method works on a copy); through a read-only place (plain parameter, read-only reference, this in an unrestricted method) only unrestricted methods are called; an unrestricted method writes no field of this and does not assign this. Not yet: static functions of a struct
- structs, step 3 (spec 11.1.5.3): strings, string? and objects (collections too) inside a struct; the struct owns them: a copy (=, !, a return, a field, a class clone) clones them, a new struct (a creation, a result, ->s, s!) is taken as it is, and they end with the struct (end of scope, replaced, a class field, a ->S parameter, a struct nobody keeps); S p lends, ->S p takes; a field that owns an object takes a new one or ->x; a struct that holds an object that cannot be cloned is an error. Not yet: collections and tuples of such structs, var b = a for them (write the type)
- static functions of a struct (spec 11.1.5.2): public static fun r64 dot(Vec2 a, Vec2 b), called Vec2.dot(a, b); through a value it is an error
- structs, step 4 (spec 11.1.5.4, 11.1.5.5): buffers arr<T>[N] in a struct (N a literal or a const; plain items: numbers, bool, char, enums, bitfields, date, time, clock, structs of plain values), stored inside the struct; read as an arr (s.m[i], s.m.len, for, printing, the arr members), written item by item or as a whole from an array literal of N items or another buffer of the same size; start values from a literal; == item by item. A local struct above 64 KB lives on the heap (freed with its scope), is filled field by field, and a plain parameter of one is passed by address
- structs, step 5 (spec 11.1.5.6, 15.9): struct<fixed> (C alignment, 4-byte bool) and struct<compact> (no alignment, 1-byte bool), plain values only (numbers, bool, char, addr, enums, bitfields, date, time, clock, buffers, structs with the same tag); .sizeof and .offset(field) on every struct (s.sizeof, Vec2.sizeof, s.offset(x), Vec2.offset(x)); extern functions take such structs by value, by address (*S name, called f(*s); &*S name, called f(&*s)) and return them; a struct without a tag given to C is an error
- structs, step 6 (spec 11.1.5.7, 2.5.1): transmute [T]x with structs (struct to struct, struct to number, number to struct): on a place it is a live view, read and written (([Whole]pair).value = 5, ([Whole]pair).clear()), = copies it; on another value it reads a copy; the view is never larger than the original; structs with strings or objects are not transmuted. '.' binds tighter than transmute ([T]s.f is the view of the field), as the parser already did
- structs, step 7 (spec 11.1.5.8, 11.1.5.9): a struct assigned to a field group with the same structure, field by field in order (s.pos = Vec2(1.0, 2.0), s.pos = v, s.pos = f()); a struct converts to a tuple (declarations, assignments, a tuple result, several results: fun i32, i32 f() { return size }) and a, b = s takes its fields in order; s.hash as the tuple of its fields (a buffer adds its items). Not yet: structs as keys of maps and sets (like tuples), structs with objects or buffers converted to tuples
- Console.readKey() (stdlib 2): as read(), and the arrows, Enter, Esc, Backspace and Tab, compared with Console.KEY_LEFT, KEY_UP, KEY_RIGHT, KEY_DOWN, KEY_ENTER, KEY_ESC, KEY_BACKSPACE, KEY_TAB; Console.moveCursor(x, y) puts the cursor at a column and a row (0, 0 top-left), so a console game redraws without clearing
- Console.setColors(Color? text, Color? background) (stdlib 2) with the 16 colours of Console.Color (Root.Console.Color, also through an alias); null is the default colour; the default colours come back when the program ends. Code examples/racer.df: a small console racing game that uses readKey, moveCursor and setColors
