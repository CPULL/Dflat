# 5. `DFoot`
`Dfoot` is a specific Dflat structure used to serialize and deserialize a tree of items. It is inspired by JSON.
- Its name is an acronym of (you decide which interpretation you prefer):
  - DFlat Formatted **Omniscient** Objects & Types – Because it can cover a huge variety of cases with ease and precision.
  - DFlat Formatted **Outrageous** Objects & Types – Because "why are you not using JSON?"
- Recursive ordered tree, JSON-like, not JSON-compatible. Meant for human-readable maps, so the key rules of [Collections](#6-collections) are looser here (details later).
- Keys: macrotype + value (signed number, unsigned number, string, bool, date); `r`, `dec`, `int`/`uns`/`real` not allowed.
- Values: any Dflat type, classes included (details later).

## 5.1 File
- It is an UTF-8 text file, with extension `.dfoot`, and compressed with a common format (Zip, GZip, 7zip, Zstandard).
- It has no versioning.
- Lines can be terminated with \n (preferred) and \r\n. Technically the whole file, can be kept on a single line
- It has 4 sections, each optional:
  - magic number: `DFoot` if present has to be the very first line (if there is no \n then we need at least one space after it.
  - `definition`: used to provide shortscuts to identify the types of data
  - `types`: used to describe custom classes, structs, enums, etc-
  - `data`: that contains the actual serialized data
- Every section is optional, including the magic number.
- The magic number  comes first and marks the file as dfoot. The other parts (`definition`, `types`, `data`) do not need to respect a specific order.

## 5.2 Definition
This section is used to define the shortcuts to identifythe types of the values.
- the data format is: `<key>:<value><type>` for example `number:100i32`
- most of the times always the same unit type is used. For example always i32 for integers or u64 for unsigned or r32 for floats.
- a set of predefined types is: `int`, `real`, and `string`
  - A number without a dot is considered `int`
  - A number with a dot is considered `real`
  - A string between double quotes (`"`) is a `string`
  - These types do not need the type specified.

Shortcuts are written `<official type>:<shortcut>`, for example `u64:l`. Two types with the same shortcut, for example `{ i32:i, i64:i }`, are a compiler (parse) error.

Examples:

```
dedinition {real:r32, r64:d} data {float:12.3, double:12.3d}
definition { int:i32, uns:u64, u32:l, r32:f, r64:d } data { a:128l, b:13.4f, c:19.0d }
```

## 5.3 Types
Every class, struct, collection, etc can be defined in types. This allows to immediately serialize and deserialize complex objects.

### 5.3.1 Classes
```
class <[namespace.]name> [<superclass,tratis,trait,...>  { <type>:<field name>, <type>:<field name>, ... }
```
Field groups have to be split. For example:
```
class Transform {
  position {
    r32 x,
    r32 y
  }
}
```
will become `class Transform { r32:position.x, r32:position.y }` inside `types`.

A serializable class (implementing the `Serializable` trait) exports its own definition with `getDFootSignature()` (see [Serializable](#512-serializable)).

### 5.3.1 Structures
```
struct <[namespace.]name> { <type>:<field name>, <type>:<field name>, ... }
```

### 5.3.1 Enums
```
enum <[namespace.]name> { <Value1>, <Value2>, <Value3>... }
```

### 5.3.1 Enums
```
bitfield <[namespace.]name> { <Value1>:<bit num 1>, <Value2>:<bit num 2>, <Value3>:<bit num 3>... }
```

## 5.4 Native values
```
<key>:<value>[<type>], ...
Key1: 12.3r32, key2:78u8, key3:"string"s1k
```
Types are always appended after the values: `{ k1:12u64, k2:12u8, 12.0r32 }`

Keys containing a space, quote, colon, comma, braces or any other special character must be between by double quotes (`"`).

A bitfield value is a number followed by the bitfield type name: `key1:142BitFieldName`

An enum value is written as `EnumName.EnumValue`


## 5.5 Identifiers and references
In case a complex object has references inside to another object, it is possible to define identifiers and references.<br>
Identifiers are unique per file. `@identifier` after a type name defines it, `@identifier` as a value references it. References to objects not included in the file are null.
```
definition {
  class Guild { string:name, Player:leader }
  class Player { string:name, Guild:guild, Pet:pet }
}

data {
  guild: Guild @g1 { name: "Owls", leader: @p1 }
  hero: Player @p1 { name: "Ann", guild: @g1, pet: null }
}
```

## 5.6 Collections
Collections are all identified by `[ ... ]`.

There are 3 types of collecitons in DFlat, identified by the traits `IndexCollection` (just values), `SetCollection` (just keys) and `MapCollection` (keys and values).
- Index collections (arrays, lists, etc.) list just the values: `[a, b, c, ...]`
- Map collections (map and hmap) list keys and values: `[key1:val1, key2:val2, ...]`
- Set collections list only the keys: `[key1:, key2:, ...]` Each key need the `:` after the key itself.
```
scores:[10, 20, 30]
bytes:[1u8, 2u8, 3u8]
members:[@p1, @p2]
ages:["Ann":31, "Bob":27]
```
An empty collection is identified as `[]`

## 5.7 Binary
```
#<bits><len, codified, 8 chars><checksum, codified,8 chars><data>
```
`bits` is the number of bits per character. The alphabet is the first 128 printable Unicode characters (base128). The length comes first, then a checksum. Binary blocks are opaque; the text values around them stay hand-editable. Multi-byte values inside binary blocks are always little-endian.

## 5.8 Dates
ISO format; hours, minutes and seconds are 0 when not specified. If `CalendarDateTime` is imported, timezones can also be mapped. Without the import, one of: a silent exception, the timezone ignored, or just the time shift added (open).

## 5.9 Lapse
```
{lapse1: nulllapse, lapse2: 123lapseyear, lapse3: 123lapsems, lapse4: 1230lapsens, lapseOverflowed: lapseoverflow }
```
The types for lapses are `lapseyear` (year lapse), `lapsems` (date lapse), `lapsens` (clock lapse) and `nulllapse`, and they can be redefined. The keyword `lapseoverflow` is the clock lapse overflow.
```
definition { lapseyear: y, nulllapse: nl } data { l1: 123y, l2: nl, l3: 123lapsems }
```

## 5.10 Typed null
Plain `null` is not used, since it could be a null of anything: `nulllapse`, `nulli32` (nullable `i32`), `nullstring`, `nullMyClass` (`MyClass` null).

## 5.11 Tree and loading
Loading a dfoot gives back a tree of `DFootNode`, where each item can be queried to understand what it is. Type creation is not done: values can be filled into existing compatible objects.

## 5.12 Serializable
```
trait Serializable<T> {
  public fun string serializeDFoot(T this)
  public fun DFootNode getDFoot(T this)
  public fun T? deserializeDFoot(string dfoot)
  public fun bool importDFoot(string dfoot)
  public fun bool importDFoot(DFootNode node)
  public fun string getDFootSignature()
  public fun bool canImport(DFootNode node)
  public fun bool canImport(string dfoot)
}
```
All custom classes, not only collections, need this trait to be serializable. Whether `canImport` checks only types or keys and types is decided by the implementation of the deserialization method.
