# 18 Globals

A global is a named object of an ordinary class, visible from the whole program and protected by a lock. It is the way to share mutable data across the program: a logger, the settings, a cache, a counter, a connection manager. It is not a static class.

```
global Logger log = Logger()
global Settings settings = Settings("app.cfg")
global Cache cache1 = Cache(123)
global Cache cache2 = Cache(500)

fun main() {
  log.write("start")
  i32 v = cache1.getOrAdd("key", 0)
}
```

## 18.1 Declaration

- `global <Class> <name> = <initializer>`: the standard declaration with `global` in front. There is no other form and no inline class (`global class` does not exist).
- Globals are declared only in the root file (`program.df`, `main.df` or `lib.df`, 16) at the top level.
- The type is a class; its usual primary and secondary constructors are used (11.1). The initializer is required.
- The class is a normal class: it can also make plain objects, which are not globals and have no lock.
- Several globals of the same class are allowed (`cache1`, `cache2`): they are different objects, each with its own lock.
- A global is visible from every file of its program or library, as `name.member`. The globals of a library are not visible outside it: they are used only by the library's own code.
- `const` values keep their rules (1.5); `global` is only for objects.

## 18.2 Life cycle

- Globals are created in declaration order, before the top-level code or `main` starts (14.1), and destroyed in the reverse order after the program ends, after its `atEnd` (14.2).
- An initializer can use only the globals declared before it (they already exist).
- The globals of a library are created before the globals of the program that uses it, and destroyed after them.

## 18.3 Using a global

- A global can only be called (`log.write("x")`), read or written through its members. Each access from outside takes the lock for that access only: the lock covers a single call. For an operation of several steps the class has one method that does the whole job (`getOrAdd` instead of a read followed by a write).
- A global cannot be assigned (`cache1 = Cache(1)`), lent (`f(cache1)`, `f(&cache1)`, `Cache c = cache1`), given (`->cache1`) or shared (`@cache1`, `%cache1`): a borrow would keep the lock for as long as the borrow lives. A copy is allowed (`Cache c = cache1!`, under the read lock).
- What comes out of a global is a copy or a value given with `->`: the caller owns it and uses it with no lock.
- A method that lends its result (13.1.1), called on a global from outside: a plain (read-only) result is copied at the call, while the lock is still held; a `&T` result is a compile error. Inside the class, calls on `this` follow the usual rules.
- A `&T` result cannot lend a global or a part of it (13.1.1).
- Fields of a global read from outside take the read lock, written from outside take the write lock, for that access only.

## 18.4 Lock

- Each global has one read/write lock: many readers or one writer. A busy lock makes the caller wait.
- Read or write is decided by the compiler for each method. A method is a write method when anything it can reach writes the global: its own code, the methods of `this` it calls, the objects it owns, and any code that calls back into the same global (18.5). When the compiler cannot tell, the method is a write method. `unrestricted` methods (1.6.2) are read methods.
- Calls on `this` inside the class take no lock (the object is already locked).
- The lock is released on every way out of the call, exceptions included.
- A global's methods are synchronous: the result goes back to the caller when the call ends.

## 18.5 Order between globals

The declaration order is the rank: a global declared earlier ranks lower. The globals of a library rank below the globals of the program that uses it, and a library ranks below the libraries it uses.

```
global C c1 = C()
global D d = D()
global C c2 = C()
// c2 can call d; c1 cannot (d is declared after c1)
```

- Each thread keeps the list of the global locks it holds.
- A call to a global the thread already holds takes no new lock: it is an internal call. An object owned by a global can call that global back:

```
class B {
  fun update() { a.note("b") }      // a is already held: internal call
}
class A {
  var bs = list<B>()
  fun addObj(->B b) { bs.add(->b) }
  fun update() { for var b in bs { b.update() } }
}
global A a = A()
```

- A call to a global the thread does not hold is allowed only when it ranks lower than every global lock the thread holds. Otherwise it raises `CallingGlobalDefinedAfterException` (15.3): the call is not made, nothing waits and no lock is taken.
- A thread that holds no global lock (any plain code, a plain object of a global's class) can call every global.
- A thread that holds the read lock of a global and needs its write lock (a read method that reaches a write method of the same global) does not wait: it raises `ReadLockBecameWriteLockException` (15.3). The compiler makes this a safety net: it infers a write method wherever a write can be reached (18.4).
- So global locks are always taken in rank order, whatever path the code takes (owned objects, other classes, traits, parent classes): they cannot deadlock. The locks of counted objects (`&@T`, 12.7) always end at their timeout (7.2.2).
- When the compiler can see that a call is always wrong (the code of a class calls a global ranked above every global of that class), it is a compile error; when it is right for every global of the class, there is no runtime check.

## 18.6 Lambdas

- A class used by a global cannot have lambdas or function values: no fields, parameters, results or calls of function types (13.3), in any of its methods. What a lambda does cannot be known at compile time.
- Code that a global reaches through the objects it owns and that calls a lambda counts as a write (18.4).

## 18.7 Threads (future)

- Waiting for another thread (a join, a channel receive) is not a lock and the order of 18.5 does not see it. When threads are added, such waits are refused or bounded by a timeout while the thread holds a global lock.
- Locks outside the program (a database row held by another connection) are not covered.

## 18.8 Compile errors

| Case | Message |
|---|---|
| `global` outside the root file | a global can be declared only in the root file (program.df, main.df or lib.df) |
| type that is not a class | a global must be an object of a class: global <Class> <name> = <Class>(...) |
| no initializer | a global needs its initializer: global <Class> <name> = <Class>(...) |
| initializer uses a later global | the initializer of global 'x' uses global 'y', which is declared after it: globals are created in declaration order |
| assignment to a global | global 'x' cannot be assigned: it always holds the object it was created with |
| lend, give or share | global 'x' cannot be lent, given or shared: call its methods, or copy it with x! |
| `&T` result from a global | a & result cannot lend global 'x': return a copy, or give the value with -> |
| `&T` method called on a global | 'm' lends its result with &, which cannot come out of global 'x': call a method that returns a copy or gives the value with -> |
| lambda in a global's class | class 'C' is used by global 'x' and cannot have lambdas or function values |
| call always out of order | global 'x' calls global 'y', which is declared after it: a global can call only globals declared before it |
| library global used outside | global 'x' belongs to library 'L' and is not visible outside it |
