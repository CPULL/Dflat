# 8. Formatting

Used in `$"{expr:spec}"` and `toStr("spec")`. Options in any order; letters act as separators; reserved letters as fill/separator chars are a compile error.

## 8.1 Numbers

A number format is a short text of options, written after `:` in an interpolated string or given to `toStr`:

```
r64 price = 3.14159
r.Console.log($"price {price:D02}")       // price 3.14
string text = price.toStr("D02w8")        // "    3.14"
```

- Each option starts with its letter; the options can be written in any order (`D02w8` = `w8D02`).
- The letters are case-insensitive, except `h` / `H` of the hex base.
- A format written in the code is checked when compiling: an unknown option is a compile error.
- Without a format, a real prints the shortest text that reads back as the same number (as C#): `3.14159`, `1`, `0.30000000000000004`; an integer prints all its digits.

#### Decimals `D`

`D` sets the digits after the decimal symbol: `D[symbol][size][rounding]`.

- `size`: the most decimals; with a leading `0` it is the exact number of decimals (zeros are added). `D0` prints no decimals.
- `symbol` (optional): the character of the decimal symbol, `.` when absent; `l` takes the symbol of the locale.
- `rounding` (optional): `u` half-up (the default), `b` banker's (half to even), `c` ceiling, `f` floor, `t` truncate.
- On an integer, a fixed size adds the decimals: `{5:D02}` → `5.00`.

| Format | `3.14159` | `2.5` |
|---|---|---|
| `D2` | `3.14` | `2.5` |
| `D02` | `3.14` | `2.50` |
| `D0` | `3` | `3` |
| `D2c` | `3.15` | `2.5` |
| `D2t` | `3.14` | `2.5` |
| `D,02` | `3,14` | `2,50` |

#### Width, fill and alignment `w` `f` `a`

- `w<n>`: the width in characters. A shorter number is padded; a longer one is printed whole (no truncation). Without `w` there is no padding.
- `f<char>`: the fill character, a space when absent. It cannot be a letter (letters start options): `f0`, `f*`, `f_`.
- `a<` left, `a>` right (the default), `a^` center.
- `a.` puts the decimal symbol at the same place for every number, so that a column lines up on it: with `D<size>`, `size` places are kept after the symbol (spaces when the number has fewer decimals). Without a `D` size it is the same as `a>`.

| Format | `255` | `3.14159` |
|---|---|---|
| `w6` | `   255` | `3.14159` |
| `w6a<` | `255   ` | |
| `w7a^` | `  255  ` | |
| `w6f0` | `000255` | |
| `w6f*a<` | `255***` | |
| `w8D02` | | `    3.14` |
| `w8f0D02` | | `00003.14` |

A column with `w8a.D2`:
```
    3.14
  -42.5
  100
```

#### Sign `S`

| Format | Meaning | `-7` with `w6` | `3.5` |
|---|---|---|---|
| `S` or `S-` | a sign only on negatives, before the first digit (the default) | `    -7` | `3.5` |
| `S+` | a sign always, before the first digit | `    -7` | `+3.5` |
| `St-` | a sign only on negatives, at the left edge of the width | `-    7` | `3.5` |
| `St+` | a sign always, at the left edge of the width | `-    7` | `+3.5` |
| `S()` | negatives in parentheses | `   (7)` | `3.5` |

With a `0` fill the sign always goes before the zeros, as with `St`: `{-5:w5f0}` → `-0005`, `{5:S+w5f0}` → `+0005`, `{-5:S()w6f0}` → `(0005)`. With any other fill it stays before the first digit: `{-5:w5f*}` → `***-5`.

#### Grouping `g`

`g` puts a separator between the groups of digits of the integer part, counted from the right.

- `g<sep><size>`: one separator and one group size, repeated: `g,3` → `1,234,567`.
- More sizes, each followed by its separator, are used in turn from the right; the last one repeats: `g,32,` → `12,34,56,789` (Indian grouping).
- A trailing `r` counts the groups from the left: `g,3r` → `123,456,7`.
- `gL` takes the grouping of the locale.
- The separator cannot be a letter or a digit.

| Format | `1234567` | `1234567.891` |
|---|---|---|
| `g,3` | `1,234,567` | |
| `g.3` | `1.234.567` | |
| `g 3` | `1 234 567` | |
| `g_3` | `1_234_567` | |
| `g,3D2` | | `1,234,567.89` |
| `g.3D,02` | | `1.234.567,89` |

#### Base `b`

`bd` decimal (the default), `bh` hex lower case, `bH` hex upper case, `bb` binary, `bo` octal, `b64` base-64 digits. Hex and binary show the raw bits (no negative hex).

| Format | `255` |
|---|---|
| `bh` | `ff` |
| `bH` | `FF` |
| `bb` | `11111111` |
| `bo` | `377` |

#### Scientific `e`

`e` prints the number as a mantissa and an exponent (8.2).

#### Special values

`NaN`, `∞`, `-∞` and `null` (a null nullable number) are printed as they are (`INF` / `-INF` on targets without Unicode).

#### All the options

| Option | Meaning |
|---|---|
| `D[symbol][size][rounding]` | decimals |
| `w<n>` | width |
| `f<char>` | fill character |
| `a<` `a>` `a^` `a.` | alignment |
| `S` `S-` `S+` `St-` `St+` `S()` | sign |
| `g<sep><size>[<size><sep>...][r]`, `gL` | grouping |
| `bd` `bh` `bH` `bb` `bo` `b64` | base |
| `e[<text>][<min>]` | scientific (8.2) |

## 8.2 Scientific format `e`

- Mantissa: one non-zero digit before the decimal symbol (as C++, C#, Rust, Python).
- `<lit>`: text printed literally before the exponent. `+` in it = exponent sign always; `-` = exponent sign on negatives only. Escapes: `\[ \] \+ \-`; everything else is literal.
- `<min>`: minimum exponent digits; `0<n>` = zero-padded, `#<n>` = space-padded; absent = unpadded.
- Combines with `D`, `S`, `w`, `f`, `a`.
- Plain `e` = `e[e+]D6a<` (exponent unpadded).
- Zero prints `0`; special values as in 8.1.

Examples with `1234.56`:

| Spec | Output |
|---|---|
| `e[E+]02D2` | `1.23E+03` |
| `e[e^]02D2` | `1.23e^03` |
| `e[e-]#3D2` | `1.23e  3` |
| `e[x10^]D1` | `1.2x10^3` |

## 8.3 Strings

| Option | Meaning |
|---|---|
| `w<n>` / `wc<n>` | width in characters / display columns |
| `f<char>` | fill |
| `a<` `a^` `a>` | alignment |
| `t<'…'` `t>'…'` | truncate keeping start / end, with marker (counted in the width) |
| `cU` `cL` `cS` `cT` | upper, lower, sentence (`Hello world`), title (`Hello World`) |
| `q` | quoted and escaped |
| `s` `sl` `sr` | trim both / left / right |

## 8.4 Dates and times

- C# custom pattern letters: `d f F g h H k m M s t y z`.
- A `time` uses only the letters of the time parts: `h H m s f F t k`. A date-only letter (`d M y g z w q i r e j`) used with a `time` is a compile error.
- Additions: `w` week, `q` quarter, `i` ISO week, `r` ISO year, `e` day of year (3 wide), `j` day of week; a doubled letter pads with a space.
- Alignment: `a<20`, `a^20`, `a>20`; no truncation.
- Locale names and first day of week: later.



# 9. Parsing
Integers, reals, `dec`, dates and times offer a `<type> <type>.parse(text[, default[, format]])` and bool `<type>.tryParse(text, &<type> result[, format])`

```
i32 count = i32.parse(text, 0)
i32 total = i32.parse(text)                       // default: the zero value
bool parsed = r64.tryParse("12.3", &amount)
i32 code = i32.parse(text, 0, "0x{bh}")           // with a format
i32 balance = i32.parse(text, 0, "{S}{S()}")       // "-10" or "(10)"
```

- `T T.parse(string text, T default = zero, string format = none)` and `bool T.tryParse(string text, &T result, string format = none)` exist for integers, reals, `dec`, `date` and `time`. On failure `parse` returns the default, `tryParse` returns `false`; no exception.


Without a format:
- Ignorable characters before and after the number are skipped; only the first number is read, and a space or any other non-number character ends it. No digits → the default.
- `.` is the only decimal symbol (English); thousands separators are not accepted, so `,` ends the number: `"1,234.5"` → `1.0`, `"1.234"` → `1.234`; as integers both give `1`. Locale separators need a format.
- Integers drop the decimals.
- Signed types: a `-` right before the digits is the sign (`"x-12"` → `-12`). Unsigned types: a minus gives `0`, or an `OverflowException` if a specific catch exists.
- Out of range saturates, or raises `OutOfRangeCastException` if a specific catch exists (silent).
- Reals: exponent accepted (`"1.5e3"` → `1500.0`); `NaN`, `∞`, `-∞`, `INF`, `-INF` are recognized; extra digits round to the nearest representable value. `dec` uses banker's rounding.

With a format:
- Layout: `"<prefix>{spec}[{alternative}...]<suffix>"`, using the 8.1 options inside the braces. The prefix and suffix are shared by all alternatives; adjacent placeholders are alternatives for the same value, tried in order, the first that matches wins.
- Parsing is strict: nothing is skipped automatically, not even spaces.
- Hex digits are case-insensitive. `\{` and `\}` are literal braces.
- Static text between placeholders makes the format invalid. A mismatch or invalid format gives the default / `false`.
- For really different inputs, call `tryParse` once per format.

Dates and times:
- Without a format, a `date` is parsed only from `yyyy-MM-dd [HH[:mm[:ss]]]`, `yyyy/MM/dd [HH[:mm[:ss]]]` or ISO 8601. Input with no zone is UTC; input with a zone is converted to UTC.
- A `time` is parsed from `HH[:mm[:ss[.fff]]]` (hours `0`–`23`) or `h[:mm[:ss[.fff]]] am/pm` (hours `1`–`12`; `am` / `pm` case-insensitive, with or without a space, at the end; `12 am` is midnight, `12 pm` is noon).

The format is specified exactly in the same way the printing format is specified.
